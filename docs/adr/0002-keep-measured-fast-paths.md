# Keep fast paths that the blocking performance checks pay for

Compiled decoders live for one request, so every PHP-FPM request compiles the decoders it uses again. The Performance
workflow blocks a change that makes the first decode in a fresh PHP-FPM request, or warm decodes, more than 3% slower
(see [Performance](../performance.md)). So the code keeps fast paths that a general rule would make unnecessary. Each
one was measured; removing one needs a new measurement that stays within the limit.

## The fast paths, as of 2026-11-02

When a change removes or renames a fast path, it updates its row.

| Fast path | Without it |
|---|---|
| Native `bool`, `int`, `float`, and `string` fields, nullable or not, become a `ScalarNode` directly in `TypeCompiler::native()`, without `NodeCompiler`. | GitHub pull request webhook 5.9% and record batch 1 4.8% slower on the first PHP-FPM decode ([#69](https://github.com/eventjet/eventjet-json/pull/69)). |
| Native class and enum fields compile through `NamedTypeCompiler::field()`, without a type tree and `UnionBuilder`. | First PHP-FPM decode 6–10% slower for the Stripe, GitHub and Kubernetes documents ([#84](https://github.com/eventjet/eventjet-json/pull/84)). |
| `PhpDocFieldType::narrowing()` compares a single PHPDoc type with a single native type, so that `PhpDocNarrowing` loads only for unions. | Loading a class costs about 4,200 instructions per request. Record batch 0, whose only field is `list<Record>` on `array`, failed the check at +3.84% (dbe5047). |
| `ClassDecoders::decodeRoot()` calls `enum_exists()` only when no decoder of the class is cached, and asks `EnumRoots` only for an enum. The rules for where a class can be decoded live in `TargetClass`, which every decode loads anyway. So a warm decode of a class root skips `enum_exists()`, and the first decode of a class root loads no extra class for these rules or for enum roots. `NullableJsonValues` reads the `JsonValue\|null` properties only for `JsonSerializable` classes without `#[Field]` and when serializing. A field checks its own node instead. | Each class adds a class load per request, about 4,200 instructions, see the row above. Checking every class without `#[Field]` made record batch 1 3.50% slower on the first PHP-FPM decode. Reading the type of every public property instead made the Stripe and GitHub documents 3.01% slower ([#114](https://github.com/eventjet/eventjet-json/pull/114)). |
| `TypeCompiler::field()` resolves a field's PHPDoc type itself, without a helper call, and `NodeCompiler` stays static, so that a field without `#[Discriminator]` allocates no compiler. | Compiling the Stripe invoice took 1.1% more instructions with a helper call per field, and 0.2% more with a `NodeCompiler` per field (callgrind, PHP 8.4 with OPcache). |
| `UnionBuilder` groups classes only when a union has several of them, so other unions load no class for discriminated unions. | Each class adds a class load per request, about 4,200 instructions, see the row above. Not measured on its own. |
| `PropertyAttributes` reads the attributes of a class's properties once, in a loop without callbacks, for `#[Field]`, `#[OtherMembers]` and `#[Discriminator]`. A field whose property declares no attribute skips its own `#[Discriminator]` lookup. Constructor parameters still look it up, because telling an ordinary one from a promoted one costs as much. | Looking up `#[Discriminator]` on every field made compiling the Stripe invoice take 1.3% more instructions than without discriminated unions, and its first PHP-FPM decode failed the check at +3.13% ([run](https://github.com/eventjet/eventjet-json/actions/runs/41614545720)). With this path it takes 0.1% more (callgrind, PHP 8.4 with OPcache, all classes loaded). |
| `PhpDocSimpleTags` reads simple doc comments without the full parser. | First PHP-FPM decode 10–34% slower, see [ADR 0001](0001-built-in-phpdoc-parser.md). |
| `PhpDocHtmlDetector` looks for an end tag only up to the last token that `PhpDocTokens::lastEndTag()` found, which searches a doc comment once. | A document whose doc comments have URLs and generics was 9.3% slower on the first PHP-FPM decode, see [ADR 0005](0005-search-doc-comments-once-for-end-tags.md). |
| Compiling a map loads no class beyond `MapNode`. `PhpDocType::mapKeys()` holds the rule for which keys a map accepts and answers a plain `string` key before it sorts union members, and `MapNode` takes its kind through named constructors and keeps it as two booleans, not as an enum. | With a `MapKind` and a `MapKeys` enum, the first PHP-FPM decode of the AWS Lambda Amazon MSK event was 5.8% slower on CI and 7.3% locally, and 4.2% locally with `MapKind` alone. Warm MSK decodes were 5.3% slower while `MapNode::decode()` asked the enum for its flags. Without the `string` shortcut, compiling and decoding the MSK event took about 2% longer ([#112](https://github.com/eventjet/eventjet-json/pull/112)). |
| `ClassDecoder::decode()` checks values that already have a field's scalar type itself, without calling the node. | Record batches 35% slower in warm decodes ([#80](https://github.com/eventjet/eventjet-json/pull/80)). A shared helper cost 13–15%. Once nodes no longer built error paths ([ADR 0006](0006-build-error-paths-while-errors-leave-nodes.md)), record batches 100 and 1000 were still 23.5% slower without it (local PHPBench, 2026-11-03). |
| `ClassDecoder::decode()`, `ScalarNode::decode()` and `ScalarNode::floats()`, which `ScalarNode::decodeEach()` calls, reject INF and -INF with `$value - $value === 0.0` instead of `is_finite()`. `ScalarNode::decode()` runs the check only for `float` nodes. | Local warm decodes, median of 5 alternating rounds against the target: with `is_finite()`, the scalar object +4.4% and long scalar lists +4.5%; with the subtraction, +2.0% and +0.0%, and no workload above +2.4% (2026-11-02). Array shapes, which decode each float through `ScalarNode::decode()`, ran +3.1% to +3.3% slower in the OPcache-off Performance workflow when every scalar node checked `is_float() && !is_finite()`; locally, median of 8 alternating rounds, that was +2.5%, the check limited to `float` nodes +0.9% with `is_finite()` and +0.8% with the subtraction (2026-11-02). |

## Consequences

Some rules exist twice: once in the general path, and once in a fast path that must agree with it. Unit tests under
`tests/Unit/Optimization` pin the fast paths, because removing one changes no result.
